# 账号 Agent、受管工作区与跨会话附件

版本：0.35.0，2026-10-28。管理服务保存凭证与执行控制状态，Agent 只取得服务端依据当前微信消息派生的工作区范围。旧版 `host.roots=["/"]` 不再赋予 Shell 宿主访问权限。

原计划的逐项完成证据、尚未通过的真实验收与当前外部条件见[验收对照表](managed-workspaces-acceptance.md)。

## 目录与权限

通过 `WECHAT_WORKSPACE_ROOT` 指定稳定存储根；未指定时使用管理服务数据目录下的 `managed-workspaces`。多账号管理器继承同一根，但账号数据使用独立哈希目录。

```text
<root>/
  public_workspace/
    projects/                 公共项目代码
    models/                   公共模型
    runtimes/                 受管运行环境
    manifests/*.json          项目入口与使用说明
  pri_workspace/<account-hash>/
    guides/                   本账号管理的指南，不向其他账号共享
    global/memory/            管理员全局笔记
    conversations/<chat-hash>/
      memory/                 Markdown 记忆
      inbox/                  收到的文件副本
      output/ tasks/ scratch/
    assets/objects/<sha256>   原件及转换素材
```

账号、来源会话、真实发送者、任务编号由 `ExecutionContext` 传递；昵称、引用内容、文件正文不能提升权限。

| 请求 | 可写目录 | 可读公共资源 |
| --- | --- | --- |
| 普通成员 | 本会话目录 | projects、models、runtimes、manifests |
| 管理员普通请求 | 本会话、`public_workspace/projects` | 同上 |
| 管理员显式 `global:true` 调用 | 当前账号私有目录、`public_workspace/projects` | 同上 |

`global:true` 是单次调用的范围，不会改变下一位群友的身份。进程按账号、会话、请求者及权限类型分开登记，运行期间检查授权是否仍有效。普通成员的提醒与本会话文件处理可以落盘，但不能使用别人的素材编号访问其他会话。

管理密码、微信登录态、API Key、发送控制队列和进程控制文件仍保存在管理服务数据目录，不挂载给 Agent。

### 发现、修改与复用工具

在当前账号启用项目开发工具后，Agent 可用 `server_tools` 查询打包的命令行工具和已安装的工具，再按当前请求的授权发现具体操作。Windows 调用 FFmpeg、FFprobe 或 Python 时可将索引返回的 `version_argv` 传给 `server_windows_process` 进行版本检查。执行脚本时把解释器、脚本路径和每个参数分别放进 `argv`，含空格的路径无需额外引号。进程编号用于查询退出码、输出或取消。

主人可用 `project_create` 建立工具项目，通过 `server_write` 创建源码，读取版本后用 `server_edit` 修改。公共项目可以通过 `project_list` 和 `project_read` 再发现。要修改已安装工具的实现，调用 `project_checkout_plugin` 获取当前会话的可编辑副本。相同安装版本会重新打开已有目录，保留修改；升级后的安装包按新摘要另建副本。私有配置和授权由宿主管理。

## 系统隔离

- Linux 使用 Bubblewrap，创建文件、进程和网络命名空间，清除环境变量，只绑定获准目录及必要的只读系统运行库。没有宿主 `/home`、盘符挂载、WSL 互操作或管理服务 Socket；子进程继承隔离。
- Windows 隐藏传输调用 LPAC AppContainer，以目录范围派生 SID 并授予该范围 ACL；没有网络能力，子进程加入关闭即结束的 Job。默认解释器为 **CMD**。旧的宿主 PowerShell 执行入口被拒绝。
- Linux `server_process(gpu:true)` 可显式开放 GPU 设备；这只表示设备挂载，不表示某一 Python/CUDA/模型组合已经通过兼容性验收。
- 隔离缺失或启动失败会返回错误，不回退为宿主执行。文件工具使用 `os.Root`，创建与编辑保留版本冲突检查；路径、符号链接、Junction 和子进程均需验收。

系统依赖：主程序使用 Go 1.26；Linux 需要可用的 Bubblewrap 和非特权命名空间。Windows 需要支持 LPAC 的系统及隐藏 Python 控制桥。管理服务自身属于可信控制面，其服务账号权限仍需由部署者管理。

**2026-10-28 的本机音乐环境记录：**Windows CMD 隔离测试通过，但已迁移的 Python/CUDA 环境在 LPAC 中启动失败，本机音乐因此使用 WSL/Linux GPU 受管执行器，不回退为不受限宿主 Shell。复制校验不等于项目运行验收；现已分别验证隔离 CUDA、Comfy 私有 Socket、真实模型 RVC 全录音139.9秒处理，以及真实YuE一分钟生成和原任务接回。它们不证明其他录音、其他时长或主观音质。音乐服务仍为按需启动，镜像构建暂停。

2026-10-29运行实例复核：先确认音乐服务原本停止、任务日志仅有1项已完成记录，再临时启动现有服务，不提交推理请求。直接读取实际Comfy推理进程的`/proc/<pid>/mountinfo`与网络命名空间：21项挂载中，当前账号私有根可写、公共根只读；磁盘挂载均位于获准工作区、系统运行库或专用IPC范围，没有额外宿主磁盘、管理控制目录或其他账号挂载，网络命名空间与宿主不同。观察的是同一服务进程，自动重启次数0；鉴权健康检查就绪并返回正确账号绑定，实际队列运行/等待均为0，任务日志SHA-256未变。确认空闲后恢复原停止状态，微信及管理端健康在线。这一复核没有创建歌曲、发送微信消息或验证音质；也不代表Windows音乐兼容已通过。

## 项目发现与迁移

Agent 先调用 `project_list`、`project_read` 读取 `manifests/*.json` 的入口、README、解释器和使用说明，再按需读代码。项目发现不需要扫描 C、D、E 盘。

项目登记文件从已固定的公共根目录句柄读取，清单目录被替换也不能转向其他账号或控制目录。仅接受普通 UTF-8 JSON 对象，读取过程有界；64 KiB 是登记元数据的格式约束，较大说明和源码仍可用 `server_read` 分页读取。单个登记文件损坏、变成链接或管道时，`project_list` 保留其他有效项目并在 `unavailable_manifests` 和管理页显示具体文件与原因；`project_read` 返回对应错误。笔记、普通文件读取/编辑与目录搜索也采用有类型的根目录打开方式，在 Unix 上非阻塞打开并复核实际文件类型，避免文件在检查后被换成管道而卡住管理服务。

目录创建逐级固定父目录句柄，再核对实际打开的目录身份；遇到祖先符号链接或Junction即停止，不先在链接目标创建目录。笔记存储在本账号固定根下解析会话、指南及全局笔记，每级目录都保留这项检查；关闭管理器时释放根句柄，文档保留。Linux的管道、祖先链接和目录替换回归，以及本机Windows无需管理员权限的Junction回归均已运行；Windows普通符号链接用例因系统权限不足跳过，未将跳过计为通过。

`server_search` 改为可续接的只读分批搜索，默认每次 100 条匹配、1000 个文件或约 5 秒返回一次；它们是起始值，不是整个任务上限。`max_files`、`timeout_seconds` 可显式调整或设为 0 取消相应分批边界。`has_more=true` 时原样传回 `next_cursor`，省略 `offset`，即使本页没有匹配也要继续；游标按真实文件字节与行号推进，不反复读取之前的文件。游标绑定路径、关键词、目录过滤与当前文件版本，变化时要求重新检索；整个目录是实时视图，不宣称为快照。

默认跳过 `.git`、`__pycache__`、`.venv`、`venv`、`node_modules`、`runtimes`；直接指定某目录作为搜索起点不会因它自身同名被跳过，或用 `exclude_dirs:[]` 检索全部目录。二进制前缀只做小块探测，不再为了检测模型文件读入数 MiB。结果分别给出实际分批参数、停止原因、累计跳过数和覆盖状态；跳过二进制、超长行、不可读文件与主动排除目录不等于证明目标不存在。旧 `offset` 保留兼容但会重扫，大目录应使用新游标。授权边界、`os.Root` 和取消机制保持有效。

`scripts/migrate_managed_workspaces.py` 接收明确的复制清单：

```json
{
  "root": "/srv/wechat-agent",
  "copies": [
    {"source": "/srv/legacy/yue", "target": "public_workspace/projects/yue"}
  ]
}
```

`exclude_paths` 按源根目录相对路径排除资源（如 `models`），保留 `comfy/ldm/models`、`comfy_api/input` 等源码包；旧 `exclude` 按递归目录名匹配，需谨慎。先不带 `--apply` 检查范围，再执行 `--plan <private-plan.json> --apply`。逐文件验证 SHA-256；重复执行复用相同文件，冲突时拒绝覆盖；拒绝链接和递归复制。迁移不删除原目录。模型、运行时、工作区、真实清单和迁移证据均不进入 Git。复制后仍需修复绝对路径、核对模型和运行时，并实际启动验证后再切换服务。

迁移的源路径需明确登记实体文件/目录；不会先解析根链接再把宿主其他文件当成原来源。树遍历及逐文件读写固定目录身份：Linux使用目录描述符，Windows逐级打开禁止删除共享的目录句柄（包含目录读取权限，只有属性查询不能防止重命名），拒绝Reparse Point/Junction。普通文件按实际类型打开；Unix非阻塞复核，FIFO等特殊文件不能卡住复制。临时副本校验、同步后采用原子“不覆盖”提交，优先同目录硬链接，不支持时只尝试系统原子不覆盖重命名；不退回`replace`或“检查后覆盖”。并发同内容文件复用原inode，不同内容保留并报冲突；已有自定义`go.mod`不覆盖，悬空标记链接不能在工作区外创建文件。新复制程序在支持POSIX权限的文件系统保留执行能力，但不复制setuid/setgid及组/其他用户写权限。已有文件的权限不擅自修改；目标新文件属于执行迁移的用户，应使用实际服务用户进行迁移并随后验收运行。

上述覆盖竞态和悬空模块标记问题已先用合成文件复现，再修复。新增16项迁移完整性检查：Windows实际执行10项（含真实Junction与父目录重命名阻止），跳过6项POSIX专用检查；Linux本地文件系统执行15项、跳过Windows Junction；本机WSL的E盘挂载执行12项、跳过Junction、FIFO及POSIX模式等4项不适用检查。该挂载支持默认硬链接路径，但不能创建FIFO，受测原子不覆盖重命名也存在能力差异；在强制硬链接不可用的情形，检查安全停止而不是覆盖。跳过不计为能力通过。测试覆盖竞争文件、来源改动、目录替换、断点复用、私有旁路文件保留、原子重命名替代及临时副本清理；没有重迁移真实模型/歌曲、没有重启微信服务或发送消息。

## 当前账号全局记忆

管理员可使用 `agent_global_search` 按会话、关键字和分页读取摘要、原消息与素材。结果携带来源会话名称、原消息时间、消息或素材编号。它不会把全部群聊全文塞进每一轮提示词，也不改变原群共享上下文。普通成员没有此检索入口。

检索按实际时间倒序比较，兼容不同 UTC 偏移和小数秒。素材使用首次来源请求的原消息时间，格式转换、上传复用和缓存刷新时间另列为 `cached_updated_at`，不会把旧文件变成最新消息。`time_basis=message/request_recorded/cache_updated/summary_updated` 区分原消息、请求落盘、旧缓存回退及摘要更新时间，缺少原时间时不伪称已知。消息和素材附带来源消息编号及已保存的发送者名称。可传 `since`（含边界）和 `before`（不含边界），均需带时区的 RFC3339；时间筛选后再分页。此检索范围为已保存的账号记忆，不等于微信端全部历史；读取失败的会话数量单列 `skipped_scopes`，取消请求会停止检索。

管理端「角色 → 任务与文档」增加受管项目、工作区状态和账号全局检索；控制台登录身份可以检查这些资料，不会伪造一条微信消息并自动发送。

账号素材检索不再要求该来源必须仍有聊天记忆。显式补读或聊天记忆过期后，已保存原件仍可通过当前账号已知的微信会话目录定位；素材本身的哈希范围不能注册新会话，其他账号、其他渠道和未知来源均排除。不为了使文件可见而新建虚构聊天记录；原消息时间筛选、普通成员隔离及管理员撤权继续生效。合成回归先复现“文件入库但无聊天记忆时检索为空”，再核对唯一结果、来源名称、原消息编号、时间边界与成员拒绝；不发送微信消息。

部署后的只读核对也从全局检索找到此前两份真实入站文件，来源会话、接收消息关联及接收时间仍保留，没有重新下载或发送。其一素材的首次旧请求原本缺少消息时间，因此顶层仍标记`request_recorded`，新补读的原消息时间留在对应请求中；不把旧首次来源改写为新补读时间。这项真实查询与上述无聊天记忆的合成回归分别记录，不能因真实文件可见就宣称手机自动入站验收完成。

能力接口报告与实际调用相同的服务端派生工作区、默认会话挂载和隔离身份，不再把旧`Host.Roots`或Windows控制桥配置描述为当前Agent权限。权限页只读展示当前账号私有与公共基准目录；保存其他设置不会把展示目录回写成授权根。原配置保留兼容，不能据此扩大实际访问范围。

管理员在私聊中检查群媒体时，`video_inspect(message_id=...)` 会根据原生消息核对同账号真实来源；用缓存 `asset_id` 时可以显式指定 `source_thread_id`。普通成员仍只能读取当前会话，管理员也不能跨账号或读取未授权来源。读取结束时再次核对来源权限，不改变发起会话。

`agent_diagnostics` 向真实管理员提供按会话、消息筛选的运行时间、事件、阶段、状态和提供商代码，支持分页，不返回原始错误正文、Key、模型提示词或后台文件。检查转写不需要把含认证信息的服务目录挂载给 Shell。

音轨存在但 ASR 返回 `ASR_RESPONSE_HAVE_NO_WORDS` 时，记录为“未识别出可转写的词”，保留实际已读时间范围。它可能对应音乐、环境声或不清晰人声，不是音轨提取/鉴权失败，也不能据此声称绝无人声。其他识别错误保留阶段与 HTTP/提供商代码，视觉成功结果继续保留。

管理页也支持公共 SenseVoice INT8 本地识别，微信语音、视频音轨和参考歌曲转写使用同一后端设置。程序与模型共享、临时音频按账号隔离，纯本地模式无网络；音乐工具令牌允许共用，服务依据管理端派生的账号身份绑定任务目录。安装、参数及边界见 [本地识别与公共工具资源](../media/local-asr.md)。

## 文件接收与跨群发送

原生客户端在 `49/6` 正文为空时投影结构化附件名、大小和消息身份；上层先识别文件，不再作为普通分享卡片。未知子类型（如尚未确认的 `49/74`）不直接视作文件。内部 CDN 凭证留在原生服务，不进入模型上下文。

接收阶段依次记录 identified、downloading、available，失败包含阶段原因。原件流式取得后计算哈希，存入账号素材库及会话 inbox；相同字节多次接收保留各次消息身份。声明的原生文件上限目前为 512 MiB；声明上限与实际已测试大小需要区分。

管理上传和原文件复用均为流式路径，按当前后台能力、真实文件大小和暂存磁盘空间校验，移除了旧网页入口及原文件复用的64 MiB拦截。上传暂存属于管理控制面，不挂载给Agent；中途失败不留下可发送的原件记录。可调整的上传超时与已验证范围见 [附件投递与核对](../media/delivery-reconciliation.md)。

管理员调用：

```json
{
  "source_thread_id": "source@chatroom",
  "asset_id": "asset-from-real-message",
  "target_thread_id": "destination@chatroom",
  "kind": "voice",
  "request_key": "one-logical-request"
}
```

工具为 `wechat_send_media`；`asset_id` 和真实文件 `message_id` 二选一，kind 支持 file、voice、image、video。兼容入口 `wechat_forward_file` 走同一链路。准备完成只表示排队，用 `wechat_operation_status` 检查实际目标回执；不要再把附件放进发起私聊的最终回复。

已有音频直接复用原件，默认转换为每段最多 60 秒的完整语音队列，不重新生歌，也不固定截成三段。尾段使用实际剩余时长，不补齐为 60 秒。来源、发起和目标会话分别保存。上一段取得可验证接受回执后，按动态随机间隔推进下一段；未知回执核对目标会话记录，进入原队列退避恢复，不重发已接受段。授权撤销或原任务取消时停止。主动分享上一批媒体或说明尚未结束时，先完成核对或处理，不继续生成新的冲浪分享积压。

批次日志、父任务关联、发送队列和每段回执分别持久保存。启动时修复批次保存与队列交接之间的中断，沿用原操作和媒体身份。任务在目标投递完成前不能按“已准备好”提前清理。

批次日志是恢复时的目标、分段和回执依据。若进程恰好在“回执落盘 → 队列移除 → 父任务结算”之间中断，启动时会去掉已接受段、恢复 Worker 的已确认状态并继续结算父任务，不重新提交已确认内容。旧恢复队列不能覆盖批次目标。仅有 `accepted` 标签但缺少可核验回执编号时继续等待核对，不能显示为已发送；完整语音分段回执可组成已接受结果。记录损坏、账号或来源身份不一致时保留原文件，停止该批次自动投递并显示待检查，不使其他聊天随之停止。

管理页「角色 → 任务与文档 → 附件投递」提供只读批次列表与详情弹窗，显示发起会话、来源、目标及各段已保存回执，名称优先显示微信名称。列表是持久事实投影，不额外调用发送接口；待确认不等于证明未送达，微信接受也不等于已验证手机播放。
